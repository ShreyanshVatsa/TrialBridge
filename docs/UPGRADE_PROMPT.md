WHY (context)
- The rule extractor reads whole eligibility paragraphs and is only 66% precise.
- The AI prompt judges only 6 criteria per trial.
- The eval labels are title-based, so they are circular.
- The fix is TrialGPT-style matching: split every trial's criteria into numbered items, settle what we can with code, have the LLM judge the rest one by one, score trials from those per-criterion labels, and measure on the real TREC labels already in eval/trec.

2. Criterion splitter (new file lib/ingest/criteria-split.ts, deterministic, no LLM)
   - Input: the CT.gov eligibilityCriteria text.
   - Output: `{id, section: "inclusion"|"exclusion", text, scope?: string}[]`, with ids I1..In and E1..En.
   - Section headers:
     - Detect them case-insensitively: "Inclusion Criteria", "Exclusion Criteria", "Key inclusion", and similar.
     - Text before any header is inclusion.
   - Item boundaries:
     - Split on top-level bullets (`*`, `-`, `•`, `1.`, `1)`, `a.`).
     - Attach nested sub-bullets and lines ending in ":" plus their children to the parent item, so "one of the following:" lists stay whole.
     - Never split on "and" or "or".
   - Cohort/arm headers ("Cohort A:", "Part 2:", "For patients in Arm B") become `scope` on the items under them.
   - Keep text verbatim and whitespace-normalized.
   - Save the criteria array in each trial's full shard record at ingest, with criteriaVersion 1, then re-run ingest. Respect `npm run budgets`; if the budget is exceeded, raise it by the measured amount and log it.
   - Tests: 30+ fixtures covering bullets, nesting, cohorts, no headers and odd formatting.
   - Gold check: download https://ftp.ncbi.nlm.nih.gov/pub/lu/TrialGPT/trial_info.json (US-government public domain; cite TrialGPT, Jin et al. 2024) into eval/trialgpt/. Its trials already have their inclusion_criteria and exclusion_criteria split into items.
     - Run our splitter on the raw text of those trials (fetch the raw text from CT.gov if it isn't in the file) and report item-count agreement and boundary F1.
     - Fix the worst disagreement patterns. Aim for ≥90% exact item-count agreement.

3. Deterministic resolver (new file lib/match/criteria-resolve.ts)
   - For each criterion item, run the existing eligibility-facts extractor on that item alone (items are atomic now, which should raise precision). Compare the result with the questionnaire answers and assign a label:
     - inclusion: "met" | "not_met" | "unknown"
     - exclusion: "excluded" | "not_excluded" | "unknown"
   - Use only these facts: age, sex, cancer group/subtype, ECOG, prior lines, brain mets, measurable disease, biomarkers, other malignancy.
   - If the patient answered "don't know" or skip, or the fact isn't asked, the label is "unknown". Never "not_met".
   - Items with scope, alternatives ("X or Y") or a time window the patient's answers can't settle are "unknown" and go to the LLM.
   - Synonym tables (new lib/ingest/synonyms/, generated by a script and committed). Use them in both the resolver and keyword search. Use only these sources:
     - HGNC gene symbols and aliases (CC0) for biomarkers (e.g., HER2 = ERBB2, PD-L1 = CD274).
     - CIViC (CC0) for variant names.
     - NCI Thesaurus (NCI EVS download) for drug names to drug class (e.g., pembrolizumab → anti-PD-1) and cancer-type synonyms.
     - Do NOT use OncoKB; its license does not allow commercial use.
     - Keep the tables small: only genes, drugs and diseases already present in our trials. Check against `npm run budgets`.
   - Fix the 7 known gaps in eval/RESULTS.md and add each as a regression test:
     - washout windows mean excluded only if within the window
     - "Known EGFR or ALK" means both excluded
     - "BRCA1 or BRCA2" means BRCA required
     - "Prior systemic therapy for metastatic disease" means previously_treated excluded
     - "not received any prior therapy" means previously_treated excluded
     - prior chemo, radiation and surgery windows

4. LLM judge (new prompts/analyze-v3.ts and a new function path; keep v1/v2 for fallback)
   - Applies to the top 10 trials after retrieval (configurable).
   - Base the prompt on TrialGPT's `get_matching_prompt()` (github.com/ncbi-nlp/TrialGPT, trialgpt_matching/TrialGPT.py, public domain). Fetch that one file and port its wording to TS, with these changes:
     - Run inclusion and exclusion as two separate sections of the request, like TrialGPT.
     - Number the patient's answers (A1..An) so the model can cite them, the same way TrialGPT numbers note sentences.
     - REMOVE TrialGPT's "assume absent facts are false" and "minimize not enough information" instructions. Our patients answer "don't know", so unknown must stay unknown.
   - Send the minimized profile (lib/privacy/minimize.ts, coarse fields only) plus ONLY the criteria the resolver left unknown, as numbered items with their ids.
   - Ask for strict JSON: `{trialId, items:[{id, label, reason (<=25 words, 6th-grade English), answerIds: string[]}]}`, where answerIds cite A1..An.
     - Inclusion labels: met | not_met | unknown | not_applicable.
     - Exclusion labels: excluded | not_excluded | unknown | not_applicable.
     - Instruct the model: if the patient info doesn't say, answer unknown. Never assume a fact is absent.
   - Validate with zod.
     - Drop unknown ids. A missing id becomes "unknown".
     - Record coverage = judged / sent.
     - Every answerId must exist in the numbered answers. A met/not_met/excluded label with no valid answerId is downgraded to unknown.
   - The UI shows OUR stored criterion text by id, so the model never quotes and there are no fabricated quotes.
   - Batch trials into requests under maxInputChars.
   - Cache by hash(trialId, criteriaVersion, promptVersion, minimized profile) in the existing cache.
   - Keep the budget, circuit breaker and failover (Groq, then Cerebras if a key is set, then the mock).

5. Score and rank (lib/match/score.ts / rank.ts)
   - Per trial:
     - incScore = met / (met + not_met + unknown + 1e-9)
     - hard = any inclusion not_met, or any exclusion excluded
   - Ranking:
     - Tier A: no hard failures. Sort by incScore, then retrieval rank.
     - Tier B: has a hard failure. Show it below the rest with the failing criterion as the reason.
   - Unknowns never lower the tier. Keep the "unknown never reduces rank" tests passing.
   - Unknown items feed the existing Find-out / ask-your-doctor list.
   - If no real LLM answered, use resolver-only labels and show a degraded-mode banner. Log the provider that actually answered.
