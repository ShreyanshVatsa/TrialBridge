# DECISIONS

- Hosting: Cloudflare free tier (no paid plan, no other host). Reason: user has no paid hosting.
- Local LLM runtime: llama.cpp (`llama-server`, OpenAI-compatible) instead of Ollama. Reason: already installed; Ollama is not.
- Local LLM model: Qwen3-14B Q4_K_M (~9 GB). Reason: strongest practical fit for 48 GB RAM; compare vs Llama 3.1 8B later if desired.
- AI providers: none enabled at start (no keys, terms unverified); mock provider only. Reason: user has no keys yet.
- Domain: none yet; use free Cloudflare subdomain until purchased. Reason: user has no domain.
- Deploy target: Cloudflare Workers with static assets (`wrangler.jsonc`, assets=./out, run_worker_first=/api/*). Reason: Cloudflare's current recommendation for new projects over Pages; supports `_headers`.
- TypeScript pinned to 5.9.3 (not 7.x). Reason: TS 7 (Go port) lacks the JS API that Next/typescript-eslint rely on.
- shadcn/ui initialized with its default base-ui style; radix-ui removed. Reason: current shadcn default; minimal deps.
- npm 11 install-script allowlist: esbuild, workerd, onnxruntime-node, protobufjs, unrs-resolver approved; fsevents denied. Reason: required native binaries only.
- Storage: D1 for backend trial-criteria copy, analysis cache, rate limits, and provider budgets. Reason: KV free tier allows only 1k writes/day; D1 free allows 100k row writes/day, 5M reads/day, 5 GB.
- Generated data (public/data, public/models, data/build) is gitignored; `npm run setup` / prebuild regenerates from committed data/seed. Reason: keep repo small; seed is committed for offline builds.
- Team split: Agent A (data, lib/match, functions, security) / Agent B (app/, components/ UI). Contract documented in API.md.
- Seed: 305 real ClinicalTrials.gov API v2 records (12 cancer-type queries x 32, recruiting, interventional, U.S. site), 302 pass validation. Reason: real data only; small enough to commit (3.2 MB).
- ZIP centroids: U.S. Census 2025 Gazetteer ZCTA internal points (public domain), committed as data/geo/zcta.csv; unknown ZIP falls back to its 3-digit-prefix average. Reason: free, official, offline.
- Embeddings: Xenova/all-MiniLM-L6-v2 q8 (P1 eval will compare bge-small), L2-normalized, stored int8 (x127). Reason: 23 MB model, 384 dims, 4x smaller than float32.
- Model + ONNX Runtime self-hosted (public/models, public/ort); browser uses the plain SIMD wasm (14 MB), not asyncify/jsep (>25 MiB Cloudflare per-asset limit); postbuild deletes the bundler's unused asyncify copy.
- CSP without 'unsafe-inline' scripts: postbuild externalizes Next's inline scripts to /_inline/<hash>.js. 'wasm-unsafe-eval' kept (required by ONNX Runtime WebAssembly). style-src allows 'unsafe-inline' (React style attributes).
- Shards live under /data/shards/<dataVersion>/ (content-hash version) so they are cached immutably; manifest/meta/lookup cache 5 min.
- Shard split threshold 700 trials per part. Reason: ~15 KB raw/trial => ~10 MB raw / ~2.3 MB gzip per part.
- Barrier rule: English requirement not flagged when another language or an interpreter is offered. Disability exclusion includes psychiatric/mental illness when no medical reason (e.g. "would limit compliance") is stated.
- Rule facts: one fact per key (directional beats "mentioned"); washout windows, "allowed", toxicity-recovery wording => "mentioned" (never penalizes). Biomarker direction decided by the marker's own suffix (HER2-, HR+) before nearby words; TNBC => HER2/HR excluded.
- Score weights (lib/match/score.ts): retrieval 1.0 (normalized RRF), conflict -0.15 each (max 3), support +0.03 (max 3), AI fit strong +0.3 / possible +0.15 / unclear 0 / unlikely -0.3.
- Analysis cache key adds a hash of the loaded trial text (plus DATA_VERSION + prompt version). Reason: cache refreshes whenever trial data changes even if the version var is not bumped.
- Rate limit: fixed hourly window in D1 keyed by sha256(salt|UTC day|IP)[:32]; missing RATE_LIMIT_SALT => fixed dev salt (dev) or random per-isolate salt (prod).
- Turnstile: fails closed in production without TURNSTILE_SECRET_KEY; dev/tests use Cloudflare's always-pass test keys.
- When real providers are enabled but all fail, the API degrades (retrieval + rules) instead of falling back to mock output. Mock is used only when no provider is enabled.
- Prompts stored as versioned TS modules (prompts/analyze-v1.ts) so both Wrangler (esbuild) and Vitest import them without loaders.
- "Not sure" search uses a lite cross-group shard (no criteria/summary/site details; [lat,lon] only) + per-trial bucket files (last 3 NCT digits) for the top results and trial page; lookup.json removed. Reason: full-card _all shard would be ~100+ MB nationally.
- Trial Q&A: crisis/eligibility/diagnosis/treatment-advice handled by deterministic multilingual rules before any AI call; answers must carry verified verbatim citations, else "not in text". 10 questions/trial/session enforced client-side; server backstop 20/trial/day per IP hash. Reason: safety must not depend on model behavior.
- Access Intelligence computed at ingestion into /data/access.json (compact count tuples per state, cancer type, state x type, and sites with 5+ trials; site-number suffixes merged). Disability exclusion intentionally includes compliance-based psychiatric exclusions (documented in API.md methodology note).
- Local LLM layer: llama-server + Qwen3-14B Q4_K_M, thinking disabled, per-fact zod validation, verbatim-quote check; cached by NCT+lastUpdated+prompt version; disagreements stored as two needsReview facts which the pre-check ignores. Sample: 4 trials at ~13-30 s/trial (~1.5-2.5 h for the seed; full national run deferred).
- Embedding model kept: MiniLM-L6-v2 q8 + int8 storage. Reason: eval shows all 6 variants within ~0.01 nDCG@10 (prod 0.819 full pipeline); bge-small is no better and int8/q8 is the smallest download.
- Eval labels are synthetic and rule-generated from titles/conditions (not clinician-reviewed); fact precision labels hand-judged by the build agent. Reason: no clinical reviewer available; documented as provisional.
- UI i18n: one typed messages file per language (components/i18n/{en,es,pt,ht}.ts) + localStorage language store, no locale routes. Reason: static export simplicity; TS enforces complete translations.
- U.S. map: equal-tile grid map built in SVG/CSS with a single-hue sequential blue ramp and per-tile labels, not react-simple-maps. Reason: no geometry dependency, small states readable, colorblind-safe.
- Theme: class-based dark mode set pre-paint by /theme-init.js (external file, CSP-safe). Reason: no inline scripts allowed.
- Partner contact: mailto built from NEXT_PUBLIC_PARTNER_EMAIL (no form). Reason: no company address known; no data-storing forms.
- National scope filter: records from the broad API query are kept only if MeSH includes Neoplasms or conditions/title contain cancer terms (drops e.g. myasthenia gravis, smoking cessation). Out-of-scope skips don't count toward the 5% validation-failure gate.
- Group shards split into balanced parts (ceil(n/700) parts of equal size). National: 24 shards, largest 2.05 MB gzip (lung), lite "not sure" index 2.6 MB gzip, 999 trial buckets (max 52 KB gzip).
- Full national public/data (174 MB, ~2k files) is produced by `npm run ingest` and deployed, not committed; the seed remains the committed offline dataset.
- E2E serves a snapshot of ./out (.wrangler/e2e-out) via `wrangler dev --assets`, so a concurrent `next build` cannot break a run. Note: always build with `npm run build` (postbuild removes the >25 MiB ORT asyncify copy and externalizes inline scripts); a bare `next build` output is not deployable.
- Priority override (2026-10-06): user has a competition submission; focus on functionality, speed, quality. Hosting, deployment, domain, CI, Dependabot deferred. Reason: user request.
- npm audit fixed without allowlists: `sharp` overridden to 0.35.5 (miniflare pinned 0.35.4); `fast-glob` overridden with a vendored tinyglobby shim (vendor/fast-glob; only @next/eslint-plugin-next's globSync is used) since braces <=3.0.3 has no patched release; the `shadcn` CLI package replaced by a vendored copy of its MIT tailwind.css (vendor/shadcn-css), use `npx shadcn@latest` to add components.
- Coverage thresholds enforced in vitest.config.ts (lines/statements/functions 90, branches 85); D1 code tested against real SQL via Node's built-in node:sqlite.
- Inline-script externalization merges each page's classic inline scripts into one deferred file under /_next/static/inline/ (Next's runtime requires currentScript under /_next/; fewer requests; no render blocking).
- zod configured jitless (z.config in lib/types/trial.ts): its eval-based JIT probe violated our CSP and is disallowed in Workers.
- E2E isolation: Playwright output dir, port, and served build snapshot are env-overridable (PW_OUTPUT_DIR/PW_PORT/PW_ASSETS) and local rate-limit counters are reset per run, because several agents run suites concurrently.
- Lighthouse measured with the default simulated mobile throttling against `wrangler dev` (gzip); targets met on landing (94) and trial (90).
- Questionnaire engine constants (lib/questionnaire/constants.ts) deviate from QUESTIONNAIRE_SPEC §2.2-2.3 after simulation (408 synthetic patients x 12 groups over the 5,726 national trials): softmax temperature 0.5 (spec 0.15 put nearly all mass on 1-3 trials, so gain vanished while ranks 4-10 could still change), stop thresholds quick 0.01 / thorough 0.002 bits (spec 0.05 stopped after ~2 questions), hypothetical sex exclusion likelihood e^-2.4 (not ~0), and fallback priors for pregnancy and sex when the catalog has none. λ = 1.2, μ = 0.4, K = 60 and the other rules are as specified.
- Retrieval/ranking sweep (scripts/eval/tune-retrieval.ts; tuning = 30 profiles, held-out = every 4th profile p04..p40; labels on the seed AND on the 5,726 national trials using the same title/condition rules): no change adopted, all weights stay. RRF k 5-100, keyword weight 0.5-3, conflict penalty 0-0.5, support 0-0.1, biomarker bonus 0-0.15, conflict cap 2-6, BM25 field boosts, prefix/fuzzy, per-shard score normalization, "X negative" terms dropped from the keyword text, v1-style keyword text: national held-out moves within +-0.015 nDCG@10 (default 0.679) and the seed disagrees in sign (about 15 candidates per profile, one swapped trial is 0.01). Lowering the criteria-text boost to 0.25 gained +0.011 tuning / +0.008 held-out nationally but was rejected: the labels read only title and conditions, so down-weighting criteria text rewards the label rule rather than relevance, and it broke the v2 >= v1 seed gate. Conflict penalty 0.3 helped national held-out (+0.015) but hurt seed held-out (-0.017) and labels cannot judge fact-based penalties, so 0.15 stays.
- Question value = information gain (bits over the top-K) + expected top-10 regret (lib/questionnaire/engine.ts `expectedRegret`: re-score the pool under each hypothetical answer, 1 - nDCG@10 of today's top 10 against the new one, weighted by answer priors); weights 1:1 (INFO_GAIN_WEIGHT, REGRET_WEIGHT, REGRET_TOP_N = 10 in constants.ts). Tuned on seed 777 / six even groups / 120 patients nationally; adaptive minus fixed nDCG@10 at k = 1/3/5/7 went from +0.119/+0.033/-0.023/-0.013 (entropy only) to +0.082/+0.034/+0.002/+0.004. Held-out (seed 20261007, all groups, 408 patients): see eval/RESULTS.md. Weights 0:1, 1:0, 1:0.5, 1:2 and TAU 0.3 were tried and lost or tied. Stop thresholds (quick 0.01, thorough 0.002) were left as they are: the regret term makes utilities so large that minUtility up to 0.1 no longer binds in quick mode, whose cap of 7 questions now decides (median 7 questions, nDCG@10 about 0.97 of the full fixed flow); raising it to 0.2 cut quality without cutting the median.
- Engine efficiency (outputs identical, tests/unit/refactor-regression.test.ts): one analysis per (state, pool, catalog, policy) shared by liveCount / nextQuestion / estimateRemaining (previously each re-scored the pool and re-ranked the questions), compiled hypotheses cached per question, fact-policy lookups memoized, pre-check compiles answers once per search, nearestSite is one pass, one BM25 index cache for search and pool. Node medians: per answer (live counter + next question + estimate) equal to the old engine even though the regret term roughly doubles one nextQuestion call.

- Fact precision gate, pass 2 (rules v4): only families >= 85% on a fresh held-out sample enable their questions: histology 92% and autoimmune 94% (n=50 each, provisional labels). hepatitis 76%, other_malignancy 78%, lines 72%, prior_drug 64%, recurrent 60%, stage 40% (n=10), biomarker_v2 67% (n=36) remain support-only. Reason: held-out showed cohort/arm context and or-alternatives in neighboring lines, and parameter (active-only vs any history) errors that clause-level rules cannot fix; no tuning on the held-out set.
- Final engine check on rules-v4 data (eval/RESULTS.md): national adaptive >= fixed at every k = 1..14 and reaches 95% of the full fixed flow at k = 6 (41% of its questions); on the seed adaptive wins at k = 1, 3, 5 but is behind by under 0.001 nDCG@10 at k = 7-9 and 13-14 (pools of about 34 trials per group), so the "every k" target is met nationally and only approximately on the seed.
